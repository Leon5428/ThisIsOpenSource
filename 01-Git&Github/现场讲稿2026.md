

## 回顾

在上一讲中，我们了解了操作系统的发展历史，什么是开源以及开源的意义，但是现在仍然面临着一个问题，就是如何高效地参与开源项目、管理代码， 以及与其他开发者协作。

我们知道，开源软件允许开发者查看、修改和分享源代码，但是，比如说，现在有一百名开发者正在共同开发一个软件，每个人都可能对源代码进行修改。那么，我们应该如何记录每个人的修改？如何知道某一段代码是谁修改的？如果有人修改代码之后引入了错误，我们又应该怎样恢复到之前的版本？

更进一步，如果两个人同时修改了同一个文件，我们又应该如何处理他们各自的修改？

所以说，如果仅仅是允许大家查看和修改源代码，并不足以解决这些问题。我们还需要一套有效的工具。

事实上，随着计算机和互联网的普及，软件开发的规模不断扩大，开发者之间的协作也变得越来越复杂。如何高效地管理代码、追踪修改，以及协调不同开发者的工作，逐渐成为软件开发中的重要问题。

而今天我们要介绍的 Git，就是解决这些问题的重要工具之一。

接下来，我们先来了解一下 Git 是如何诞生的。

## Git的前世今生

在正式介绍 Git 之前，我们先来了解一下 Git 的诞生背景。

最初开始开发 Linux 的时候，开发者们并没有使用专门的版本控制系统。大家交流代码、提交补丁，主要依靠电子邮件。

具体来说，来自世界各地的开发者会通过电子邮件向 Linux 的创始人 Linus Torvalds 提交自己的代码修改，Linus 则负责审查这些补丁，并将合适的修改整合到自己维护的 Linux 内核代码树中，最后再发布新的内核版本。

但是，这种开发方式存在一个非常明显的问题，那就是代码的版本管理十分困难。

例如，当一个新的 Linux 内核版本发布之后，如果我们想知道这个版本相较于上一个版本究竟修改了哪些内容，就需要借助 `diff` 这样的工具，对两个版本的代码进行比较。

而如果我们想进一步知道某一段代码是谁修改的、为什么要修改，或者希望恢复到之前的某个版本，那么整个过程就会变得更加复杂。

因此，随着软件项目的规模不断扩大，人们逐渐意识到，我们需要一种专门的工具来管理代码的历史版本，这就是版本控制系统。

版本控制系统，英文叫作 Version Control System，简称 VCS，是一种用于记录文件或项目随时间发生的变化，并对这些变化进行管理的工具。

它主要能够帮助我们完成以下几件事情：

首先，记录每一次修改。也就是说，我们可以把项目在不同时间的状态保存下来，形成一系列历史版本。

其次，查看不同版本之间的差异。例如，我们可以知道某次修改增加了哪些代码、删除了哪些代码。

第三，恢复到过去的某个版本。如果某一次修改引入了严重的错误，我们就可以利用版本控制系统找回之前的代码。

第四，追踪修改者以及修改原因。对于每一次提交，我们都可以记录是谁进行了修改，以及这次修改的目的是什么。

最后，也是对于开源项目而言非常重要的一点，就是协调多个开发者共同开发一个项目。即使不同开发者同时修改代码，版本控制系统也能够提供相应的机制，帮助他们整合各自的工作。

所以，版本控制系统实际上解决了软件开发中的一个核心问题：如何有效地管理不断变化的代码，以及如何让多个开发者共同维护同一个项目。

那么，既然版本控制系统这么重要，Linux 开发者后来使用了什么工具呢？Git 又是在什么情况下诞生的呢？

这就是我们下一页要介绍的内容。

在上一页中，我们介绍了什么是版本控制系统，以及为什么软件开发需要版本控制系统。那么，接下来我们就来看一看 Git 究竟是如何诞生的。

实际上，Git 并不是 Linux 内核开发团队使用的第一个版本控制系统。

2002 年，Linux 内核开发团队开始使用一款名为 BitKeeper 的商业分布式版本控制系统。

BitKeeper 是由 BitMover 公司开发的。当时，BitMover 公司允许 Linux 内核开发社区免费使用 BitKeeper，因此 Linux 开发者得以利用这一工具管理代码，极大地提高了开发效率。

但是，这里存在一个问题：BitKeeper 本身是一款专有软件，并不是自由软件。虽然 Linux 开发者能够免费使用它，但是他们并不能像修改 Linux 内核一样，自由地修改和分发 BitKeeper 的源代码。

到了 2005 年，BitMover 公司与 Linux 内核开发社区之间发生了矛盾，最终导致 Linux 内核开发社区失去了免费使用 BitKeeper 的权利。

这就产生了一个非常尴尬的局面：Linux 本身是世界上最著名的开源项目之一，但是开发 Linux 所依赖的版本控制工具却是一款专有软件，而且这款工具的开发公司还能够决定是否允许 Linux 社区继续使用它。

面对这样的情况，Linux 的创始人 Linus Torvalds 决定自己开发一套版本控制系统，以满足 Linux 内核开发的需求。

当然，Linus 并不是想简单地重新实现一个 BitKeeper。他希望新的版本控制系统能够支持大规模的分布式协作，具有足够高的性能，同时保证代码历史的完整性。

于是，2005 年 4 月 7 日，Git 的第一个提交诞生了。

这里值得注意的是，Git 从一开始就是为 Linux 内核这样的大型开源项目设计的，因此它非常重视性能、可靠性以及分布式开发能力。

后来，随着越来越多的开发者开始使用 Git，它逐渐发展成为今天广泛使用的版本控制系统。

顺便提一下，BitKeeper 后来也发生了一些变化。2016 年，BitKeeper 正式开源，采用 Apache 2.0 许可证。不过，到了 2020 年，BitKeeper 停止了开发。

回顾这段历史，我们会发现一件非常有意思的事情：Git 的诞生本身就与自由软件和开源运动密切相关。

也正是因为 Linux 社区无法继续依赖一款专有的版本控制工具，才促使 Linus 开发出了 Git。
